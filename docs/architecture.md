# How the engine carries work

A caller supplies intent, context and configuration to the Agent SDK. The runtime creates a run identity and cancellation controller, selects direct or council execution, and streams events back to the caller. Tools pass through the existing workspace, allowlist and permission boundaries. A malformed attempted tool call produces a bounded repair turn rather than an empty success.

The provider layer owns protocol details. Dispatch adds the selected operating context, rate and budget controls, then calls the provider. Provider-reported usage, calculated estimates, transport errors and unknown outcomes keep their own meanings. Optional trace callbacks receive attributable source events; a failed observer does not make an entered provider operation safe to repeat.

## Context that reaches the next action

The direct SDK path accepts a trusted host memory callback separately from model-facing configuration. It selects references, admits them before inspecting their payloads, and packs whole admitted values within the available budget. Memory is rebuilt for each turn and is not copied into the retained conversation transcript. A timeout or unavailable optional context does not leave the ordinary loop waiting indefinitely.

An output review can compare the actual result against sourced operator words and selected policy inputs. A supported drift finding can cause one concrete corrective turn. A second unresolved finding stays visible; it does not create an endless correction loop or declare the task accepted. Review receipts and later output are separate observations.

Topology execution retains the mandate, agent assignments, phases, results and source-bound session records. Per-agent continuity can carry selected earlier observations into later frames. A model label is not an agent identity, and a stored record is not proof that a later model received or used it. The code exposes those boundaries instead of flattening them into a single memory-success flag.

## Evaluation and adaptation

Several implemented loops use the data generated by work:

| Mechanism | Input and consequence | Limit |
|---|---|---|
| Dispatch resilience | Terminal outcomes and observed latency update circuit and latency state; later dispatch uses those controls. | Availability and latency do not establish output quality. Streaming does not update every buffered reliability measure. |
| Topology analysis | Phase results feed calibration, overlap/correlation heuristics and marginal-value observations. | Agreement is not independent confirmation, and a heuristic is not causal proof. |
| Persona path | Selected experience and measured grading inputs can update bounded persona state under its explicit controls. | The optional native component and any empirical interpretation retain their own qualification. Trait coordinates are not diagnoses of people. |
| Sourced output review | Actual output, original intent and prior findings inform a bounded correction turn. | A review verdict does not grant authority or certify the whole project. |

The code for an unqualified legacy automatic source updater is not included. Evaluation and adaptation remain useful without allowing a helper to stage an entire working tree or call a module import a test suite.

## Protocols and shared work

MCP exposes curated prompts, resources and tools; its handlers retain the host's permission context. ACP translates sessions, streaming updates, permission requests and cancellation onto the Agent SDK. The engine can be used in-process without either protocol. Network or process transports remain adapters around the same selected behavior.

Company and child execution retain explicit budgets, identities, stop conditions and run controls. A child result does not close its parent's whole task. Immutable local session records are the ordinary public storage mechanism; a host may supply its own explicit publication callback. This is separate from any private native persistence implementation.

## Ground Zero correspondence

Ground Zero supplies the independently maintained framework and source provisions. Illuci records the exact source revision it has received in [`core/governance/adoption/`](../core/governance/adoption/). The engine's carried instructions, hard checks, optional evaluators and evidence are then described separately. No framework file becomes an authenticated permission, and a newer upstream document is not silently selected at runtime.
